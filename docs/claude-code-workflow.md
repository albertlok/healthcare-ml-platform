## Architectural Decisions Made with Claude Code

### 1. Delta Lake MERGE vs overwrite for silver
Claude suggested a MERGE upsert (not overwrite) for the silver layer so the job is idempotent without reprocessing entire partitions. This is the Databricks-recommended pattern for mutable silver tables.

### 2. SCD2 two-step merge
The SCD2 implementation uses two separate operations — (1) close stale rows, (2) insert new rows — rather than a single complex MERGE. Claude Code explained this avoids a race condition where a single MERGE with `whenMatchedUpdate` + `whenNotMatchedInsert` can produce duplicate current rows if the same patient_id appears twice in the incoming batch.

### 3. DuckDB for local dbt vs Snowflake
Claude Code recommended DuckDB as the local dbt target (zero infra, Snowflake-compatible SQL) with a `profiles.yml` swap to Snowflake for prod. This means all SQL logic is testable for free in CI.

### 4. Offline LLM fallback in RAG API
The `_build_answer()` function in the RAG API tries Anthropic Claude if `ANTHROPIC_API_KEY` is set but falls back to a rule-based sentence extractor otherwise. This makes the entire project runnable for free with no external API dependency.

### 5. `scale_pos_weight` for class imbalance
Claude Code identified that with ~15% no-show rate, the XGBoost model needs `scale_pos_weight ≈ 5.67` to avoid predicting "showed up" for every case. Also suggested lowering the classification threshold to 0.35 (vs default 0.5) to reduce false negatives.
